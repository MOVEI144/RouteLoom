### Added

- Device membership API (#191): `Device::membership()` returns the stage
  (Unprovisioned, Joining, PendingAuthority, Member, Removed, Recovery,
  Leaving), site, 64-bit network, NodeId, generation, granted role, time of
  the change, boot, reason id and the operation in progress.
  `DeviceObserver::on_membership` reports each change once.
- `Device::leave()`: the device leaves its site on its own. The intent is
  written to RLX1 (schema 2) before anything is erased and a power cut
  resumes it. Site membership, resume state and site trust are erased; the
  device identity, boot counter, board config, keys and join policy stay.
  Untransmitted sends end `CANCELLED_LEAVE`. The device then restarts
  unassigned with no holdoff and may rejoin any site, the one it left
  included. The old site is not notified.
- `Device::request_join()`: an unassigned device scans now; a member
  re-verifies its membership. `DeviceObserver::on_operation` reports
  JOINED, JOIN_DENIED, JOIN_PENDING, JOIN_TIMEOUT or LEFT.
- Device connectivity (#192): `Device::connectivity()` is Unknown,
  Reachable, Degraded, Isolated or Sleeping toward the site's gateways,
  from authenticated evidence only (authenticated communication heard directly from the gateway or
  end-verified messages, control replies and receipts from it). Isolated after
  120 s without evidence; membership is kept. API1 `nodes.list` and
  `nodes.get` report `connectivity` as the gateway sees each node.
- Join policy (#193): `Device::set_join_policy(policy, expected_revision)`
  sets the avoid holds, the removal holdoff, the retry cap, an isolation
  notice, the unassigned start spread and the requested role. Values are
  range-checked, the revision is compare-and-set, and the policy is stored
  in RLJP1. The defaults are the previous fixed values.
- `SendOptions::coalesce_key` (BEST_EFFORT only): a new send replaces an
  untransmitted one with the same key to the same destination, which ends
  `CANCELLED_SUPERSEDED`.
- `Device::send_applied`, `set_applied_sink` and `complete_applied`. At most
  four deferred APPLIED tickets are open; a further request is refused as
  Capacity without calling the endpoint.
- `SecurityProfile::Candidate`, reported by `Device::capabilities()` for
  MemberEdhoc. `DeliveryAssurance::source_role` carries the origin's
  verified member role.

### Changed

- Calls into `Device` from inside a Device callback return `Busy`.

### Fixed

- A destination accepts an APPLIED request into an acknowledged or expired
  result slot; it no longer refuses after eight requests per minute.

- Reject coalescing on APPLIED sends and callback reentry through deferred
  APPLIED endpoints. Revoke/leave invalidate pending receiver tickets.
- Stop admission and dispatch as soon as the leave intent is durable; expose
  the Owner stage immediately and report erasure failures as Recovery.
- Apply the join retry ceiling to zero-touch scan and failure backoff too.
- API1 connectivity requires authenticated node evidence and uses a
  monotonic clock; route entries and wall-clock jumps cannot renew it.
