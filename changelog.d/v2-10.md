### Removed

- **Breaking:** the dev-PSK fixture security mode (Kconfig
  `ROUTELOOM_SECURITY_MODE_*` choice "legacy-fixture") is gone. Select
  `ROUTELOOM_SECURITY_MODE_DEV_RAM` (default) or
  `ROUTELOOM_SECURITY_MODE_MEMBER_EDHOC`. The Kconfig symbols only that mode
  used are gone as well: `ROUTELOOM_PEER_NODE_ID`, `ROUTELOOM_PEER_MAC`,
  `ROUTELOOM_DISCOVERY*`, `ROUTELOOM_TELEMETRY_REMOTE`,
  `ROUTELOOM_CONFIG_PROFILE`, `ROUTELOOM_CONFIG_COSE_KEY_HEX`,
  `ROUTELOOM_TRUST_STORE`, `ROUTELOOM_USB_DEV_SECRET`,
  `ROUTELOOM_MIGRATION_AUTHORITY` and `ROUTELOOM_MIGRATION_SELF_AUTHORITY`.
  Remove them from your `sdkconfig`; boards running such an image need a full
  erase and re-provisioning (as for every v2 image). No image writes the
  per-peer `rlcounter`/`rlreplay` NVS namespaces any more (issue #37); the
  `security legacy-state` console verb still purges them on old boards.
- **Breaking:** `routeloom_espnow` no longer ships
  `DevelopmentPskSecurityProvider`, `NvsCounterStore`, `NvsReplayStore`,
  `NvsSleepStorage`, `DevPskCommitVerifier`, the espnow `DevScopeProvider` or
  `EspNowAutonomy`. `kSecurityNvsPartition` is now declared in
  `routeloom/nvs_sdkv1_store.hpp`.

### Changed

- **Breaking:** the observation and receive-assurance security profile id 3
  (the removed fixture) is reserved: gateways never send it and the host
  rejects an ingress assurance tail that carries it. API1 `assurance.profile`
  no longer returns `legacy_fixture`.
- The maintenance (setup) console always binds to its own chip, role,
  security mode and station MAC; it no longer has an unbound mode.
- meshviz accepts only DevRam and MemberEdhoc firmware bundles.
- On ESP32-C3, `CONFIG_ROUTELOOM_CONFIG` requires the endpoint resource
  profile: the build stops with an error for the relay or gateway profiles,
  whose static RAM would fall below the radio start floor with the config
  journal (a DevRam relay image measured 16,372 B free against 19,456 B).
