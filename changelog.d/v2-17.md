### Added

- Device C API 1 (`routeloom/device.h`, `rl_dev_*`): the C form of
  `routeloom::Device`. `rl_dev_start(observer)` boots the node from the
  component Kconfig; send, group send, cancel, delivery, APPLIED (always
  asynchronous tickets on the receiving side), membership, connectivity,
  `request_join`, `leave`, join policy and capabilities are one call each,
  and `rl_dev_post` is the only call another task may make. Every struct
  starts with `{struct_size, version}` (`RL_DEV_API_VERSION` 1); layouts are
  pinned in `protocol/abi-golden/device-api1.json`.
  Invalid observers and repeated startup are rejected without replacing
  callbacks; state reads in callbacks return Busy. P05-C covers bounded
  posting, duplicate ticket completion and C delivery/result reads.
  Jobs posted by callbacks wait for the next Owner pass; each drain uses
  the job count captured before polling the runtime and Owner.
- Examples `examples/endpoint_c` (C) and `examples/standalone_gateway` (a
  gateway image whose application serves the members with no host).
  P06-O runs the standalone application's actual response loop with two C
  endpoints after the host disconnects (10 exchanges per endpoint).
- CI builds `tests/idf_consumer`, a C and C++ project that uses the SDK only
  through the component-manager git dependency, on ESP32-C3, -S3, -C5 and
  -C6.
- MemberEdhoc firmware cells inspect the linked image for the quick-start
  development key (binary and hexadecimal forms). Boot logs explicitly
  identify DevRam as Development and MemberEdhoc as Candidate.

### Changed

- `examples/espnow_node` is now `examples/endpoint_cpp`.
- Product firmware (`reference_node`, `bridge_node`, `bench_node`) defaults
  to MemberEdhoc (Candidate). DevRam remains explicit in quick starts and
  examples. The default-switch commit requires the H2 hardware acceptance
  record before merging.
