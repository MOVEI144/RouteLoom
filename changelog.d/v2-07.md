### Added

- `components/routeloom_device` with `routeloom::Device`: the one ESP-IDF
  boot path for every image (NVS, boot session, sdkv1 stores, BoardConfig
  gate, security owner, ESP-NOW runtime, USB bridge on gateways) and the
  application facade `begin`/`step`/`next_deadline`, `post` (the only call
  from another task; 8 jobs, full is `Busy`), `send`, `send_group`, `cancel`,
  `delivery`, `observe` (`on_message`/`on_delivery`) and `capabilities`.
  `enable_observation()` serves the read-only observation source on a
  non-gateway image; images that do not call it leave that code out.
  `Device::start()` runs the node on a dedicated Owner task sized by
  `CONFIG_ROUTELOOM_OWNER_TASK_STACK_SIZE` (16 KiB) and
  `CONFIG_ROUTELOOM_OWNER_TASK_PRIORITY` (1);
  `device_config_from_kconfig()` fills `DeviceConfig` from the build.
- `CONFIG_ROUTELOOM_DEV_KCONFIG_IDENTITY` (DevRam only, default off): take
  the node, network, channel and PSK from Kconfig instead of a provisioned
  BoardConfig. `examples/espnow_node` enables it.
- CI builds `examples/espnow_node` and `tests/idf_consumer`, an ESP-IDF
  project that fetches `routeloom_device` from a pinned Git revision outside
  the checkout. The Device's ESP-NOW and core dependencies use that revision.

### Changed

- **Breaking:** `components/routeloom_node_boot` (`run_node`,
  `NodeBootHooks`) is replaced by `routeloom_device`. The SDK Kconfig
  symbols moved from the apps' `Kconfig.projbuild` into the component
  `Kconfig` under the same names; an app keeps only its own symbols.
- `bridge_node`, `reference_node`, `bench_node` and the example boot through
  `Device` only. `CONFIG_ESP_MAIN_TASK_STACK_SIZE` is back at the ESP-IDF
  default in those images; the Owner task carries the 16 KiB budget.
- The Owner mesh harness peer boots through `Device` (`open_storage` and
  `begin`), so the E2E rows exercise the production boot order.

### Fixed

- A factory-fresh Member (sealed identity, no site record) boots its
  lifecycle on the first adoption instead of parking in `StorageBlocked`,
  so an `identity_only` device can join over a relay.
- Jobs posted during an Owner pass wait for the next pass even when fewer
  than eight jobs were queued. A failed DevRam startup clears its temporary
  PSK before returning.
