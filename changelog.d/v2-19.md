### Added

- Optional authenticated unicast AppObject transfer (default OFF), with explicit C/C++ Device APIs and API1 `objects.submit/get/cancel`. Objects up to 4096 bytes use 121-byte chunks, a two-frame window, bounded receive/completion records and Bulk pacing; ordinary sends keep their 128-byte limit.
- HostLink object upload and verified `objects` subscriptions, wire golden vectors, parser fuzzing and real-Owner transfer scenarios. Existing config reassembly uses the shared non-owning assembler without changing its wire format.
- Object completion validates live security contexts and deadlines, including time in the receive driver queue; conflicting manifests abort assembly. RX loans cannot overlap active TX loans, gateway receive slots wait for USB egress, and physical Bulk pacing includes OFF relays and hop retries. Extension HOP_ACCEPT and host request routing now cover object traffic.
- Authority endpoint reassembly also uses the shared assembler, preserving its contiguous chunk grid, inclusive timeout, digest scratch clearing and existing 4512-byte size guard. Naturally aligned AppObject source floors retain every peer, boot and context while using less padding.
- A newer authenticated source boot retires its old receive assembly before checking receive capacity, so a full slot cannot deliver a retired transfer.
- Host object commands retain their admitted HostLink session in the writer queue and are dropped when the operation deadline, reply timeout or session retirement makes them stale.
- The C5 bridge AppObject build requires the existing `gateway_small` profile to satisfy the RAM guard; the default profile and guard stay unchanged. C3 bridge ON adds 10,408 bytes of static RAM, above the 5 KiB target. Compared with the previous implementation, C3 ON saves 296 bytes of RAM and 112 bytes of flash; shared authority reassembly adds 960 bytes of flash to OFF without increasing its static RAM.
