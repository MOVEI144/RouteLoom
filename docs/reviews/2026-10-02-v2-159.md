## ② 指摘と修正（重要度順）

### P1：多 byte CID を integer と誤判定し EDHOC compose が失敗する

`components/routeloom/third_party/libedhoc/library/core/edhoc_connection_id_internal.c:59`。
C_I=`18 18`、C_R=`19 01 00` を設定すると、1 byte に限るべき compact 判定が
CBOR integer と解釈する。修正前の live peer は message_1 compose に失敗
（libedhoc -110）し参加を開始できない。
[RFC 9528 §3.3.2](https://www.rfc-editor.org/rfc/rfc9528.html#section-3.3.2) では、
integer 表現は1 byteの -24..23 に対応する CID だけで、それ以外は bstr を使う。
`length == 1` の gate を追加。両方向の本物の C++ / Rust exchange と
exporter 一致を `live_multibyte_integer_shaped_connection_ids` で確認した。
VENDORED.json に upstream blob と理由を登録し、patch を除くと upstream blob に戻る検査を追加。

### P1：Rust の group security context が C++ と一致しない

`host/routeloom-wire/src/lib.rs:579`、`:597`。
network=1、origin=previous_hop=2、destination=next_hop=broadcast、
RouteUpdate / BestEffort / hop=1 / epoch=1 では、Rust が Link、C++ が GroupLink
を選ぶため ciphertext / tag が異なる。C++ 生成の新規共通 vector
`protocol/golden/valid/broadcast_route_update.json` は C++ 合格、修正前 Rust 失敗。
また GROUP_DATA の context には鍵導出に要る message.session と group destination が欠けていた。
鍵の入力は既存の `docs/design/sdk-v1/03-key-hierarchy.md` §6.1 と
C++ `wire::end_context` / `GroupSecurityProvider::material` が正本。
GroupLink=3 と group_epoch / sender_boot / group_id を追加し provider へ渡す。
共通 vector と実 codec の seal/open provider 境界試験で一致を確認。
C++ と同じ broadcast header 制約・非zero epoch 検査も追加した。

### P2：Extension(u8) が registry 外の型を emit できる

`host/routeloom-wire/src/lib.rs:651`。
有効な通常 header の frame_type に `Extension(0)` / `Extension(96)` を入れると、
修正前の encoder は、自分の decoder と C++ が拒否する frame を emit する。
`Extension(25)` のような既存型の別表現は Group context の選択も迂回する。
Extension の範囲64..95を encode 前に強制し、範囲内の正常値と範囲外・別型を表で検査した。

P3：Rust crate doc の epoch/counter offset 表が旧 u16/u64 のままだった（`host/routeloom-wire/src/lib.rs:33`）；実装どおり u32/u48 に修正。

## ③ 受入判定・維持した契約

この担当範囲では受入可。未解決 P0/P1 は0、P2も修正済み。
wire header 88 bytes、型番号、既存 golden bytes、HKDF/HMAC ラベル・MAC幅、
HostLink v2 transcript、保存 schema、capacity/security mode/capability の既定は維持した。
wire golden 再生成で既存 vector の差分はなく、新規 broadcast vector だけを追加した。
Rust SecurityContext の struct literal 利用者は3 fieldを初期化する必要がある
（通常 Link/EndToEnd は全て0）。SecurityScope の exhaustive match には GroupLink 分岐も要る。
v2.0正式化前の修正であり、wire互換は維持される。
