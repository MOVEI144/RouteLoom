# M08 hardware approximation — acceptance remains red

Base: `581d1ebcdecfa01986b220757df0f147deae634b` (#261 included).
This is a host fault-injection record, not an on-board qualification.
No production SDK or firmware code changes are proposed.

## Findings

#261 (`7fd589a3`) rotates unconfirmed End handshake chunks, prevents duplicate
progress replies from starving the tail, bounds chunk sends by the existing
exchange timeout, and retries End M4. It repairs cold End establishment, but
does not change DATA admission, terminal retention or the radio retry path.
Its existing small32 overload reproducer still fails after the merge.

The C3 gateway_small default has 32 dedup entries and 28 terminal pins
([node.hpp](../../components/routeloom/include/routeloom/node.hpp)). A delivered
DATA retains its terminal record until its remaining message horizon plus
30 seconds, capped at 60 seconds from first receipt
([node.cpp](../../components/routeloom/src/node.cpp)). The tracked burst uses
the unchanged 30-second lifetime. Five members each admit eight of their
16 requests: 40 accepted messages. The first 28 pins cannot expire during
the remaining messages' lifetime. Thus even a lossless radio cannot deliver
99% of this single burst under those capacity and retention contracts.
For sustained traffic, four admitted messages/second also exceeds 28 pins
with at least 30 seconds of residence per delivered message.

| Area | Code evidence and limit of the conclusion |
| --- | --- |
| ESP_NOW_SEND_FAIL | Runtime stages a failed completion; Owner delivers it to `MeshNode::on_radio_tx_result`. Core retries with a fresh link counter and bounded jitter. Two consecutive MAC failures invalidate the next-hop route. A binding-matched early HOP_ACCEPT wins over a failed MAC completion. Failures are not silently treated as successes. |
| Collision retries | Existing deterministic jitter is 0–20 ms normally, 20–100 ms while BUSY is active; RF, BUSY and physical attempts have separate existing bounds. No jitter increase is needed to pass the below-quota fault control. |
| HOP_ACCEPT timing | Wait starts after MAC completion, not submission. Initial RTO is 60 ms; measured RTT adapts within 20–250 ms. An overloaded receiver can refuse/drop before ACK, so HOP_ACCEPT_TIMEOUT alone does not establish an RF collision. |
| Owner/RX | RX event queue and each drain are bounded at 48. Reserved completion is drained first. H7r2 reports gateway wall occupancy up to 74.429 ms; pure occupancy and time-correlated RX saturation/MAC failures/terminal quota were not established by this investigation. |
| Frame work | A successful one-hop Reliable exchange uses DATA, HOP_ACCEPT(DATA), END_RECEIPT and HOP_ACCEPT(END_RECEIPT), before losses or background control. END_RECEIPT itself requires hop acceptance. |
| LR | Adapter configures LR 250 kbps. The existing `(encoded bytes + 96) * 32 us` estimate gives about 6.94 ms for 1-byte DATA, 7.10 ms per 22-byte HOP_ACCEPT and 7.87 ms for the 30-byte END_RECEIPT: about 29.0 ms for the four-frame exchange. This excludes actual contention/driver retries and is not measured airtime. |

The evolving H7r2 draft was read in the sibling worktree, without changes.
Its corrected five-source repeat (`repeat/m08/corrected-star-window`, base
`497c7617`) records 249/1,200 accepted deliveries, all five BURST_ARMED receipts,
948 HOP_ACCEPT_TIMEOUT terminals and three unobserved accepted terminals.
Queue drain samples are 1.2–8.2 seconds. Earlier unarmed/fixture-unisolated
windows are separate evidence. These observations are consistent with
receiver admission pressure, but do not prove that it alone explains the
physical-radio result. The private console and RF/Owner effects remain
unqualified; the acceptance threshold is unchanged.

## Fault model and results

Use the real Device/Owner peer, gateway_small for G and full for members.
No ACK or receipt is fabricated. After cold boot with `--crypto-ms 154`,
radio delivery and unicast completion each have 10 ms delay. The new model
loses all simultaneously audible unicasts to the same receiver in one
1 ms step and reports failed MAC completion at the configured callback time.
The gateway Owner is held for 25 ms at burst start while RX callbacks still
queue. Broadcast interference, overlapping airtime across different steps,
capture and PHY retry behavior are not modeled; this is an explicit fault
control, not RF calibration.

| Targeted case | Result |
| --- | --- |
| Existing #261 control, four/source | PASS: 20/20 receipts and unique receives; zero terminal refusals; ACK loss rules both fired. |
| Existing #261 overload, 16/source | FAIL: 28/40 delivered; 46 terminal refusals; source counts 4,7,6,4,7 of eight. |
| New contention control, four/source | PASS: 20/20; 13 collision losses, zero terminal refusals. |
| New contention overload, 16/source | FAIL: 28/40; 36 collision losses, 70 terminal refusals; source counts 8,4,8,8,0 of eight. |

Every admitted key had one terminal callback; every Delivered key matched
one verified receive; queues were empty at 30 seconds in these cases.
The overload remains an explicit ignored red acceptance test, executed
with `--ignored`, not a green test of degraded throughput. Below-quota
success does not qualify sustained M08, route flap or on-board delivery.

## Reproduce

Build only the two peer targets in sanitizer Debug trees with `-j4`:

```sh
cmake -S . -B build-v2 -DROUTELOOM_ENABLE_SANITIZERS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build-v2 -j4 --target routeloom_owner_mesh_peer routeloom_joiner_interop_peer
cmake -S . -B build-v2-small -DROUTELOOM_ENABLE_SANITIZERS=ON -DCMAKE_BUILD_TYPE=Debug -DROUTELOOM_RESOURCE_PROFILE=gateway_small
cmake --build build-v2-small -j4 --target routeloom_owner_mesh_peer routeloom_joiner_interop_peer
export ROUTELOOM_MESH_PEER="$PWD/build-v2/tests/cpp/routeloom_owner_mesh_peer"
export ROUTELOOM_OWNER_PEER="$PWD/build-v2/tests/cpp/routeloom_joiner_interop_peer"
export ROUTELOOM_MESH_PEER_GW="$PWD/build-v2-small/tests/cpp/routeloom_owner_mesh_peer"
export ROUTELOOM_OWNER_PEER_GW="$PWD/build-v2-small/tests/cpp/routeloom_joiner_interop_peer"
export CARGO_BUILD_JOBS=4
cd host
cargo +1.85.0 test -p routeloom-host --bins mesh_m08hw_contention_within_terminal_quota -- --nocapture --test-threads=2
cargo +1.85.0 test -p routeloom-host --bins mesh_m08hw_contention_overload_small32 -- --ignored --nocapture --test-threads=2
cargo +1.85.0 test -p routeloom-host --bins site::owner_mesh::uplink::mesh_uplink_star_ -- --include-ignored --nocapture --test-threads=2
```

Fmt/clippy and scenario validation pass. No full ctest, Rust live workspace,
firmware matrix, quick/selfcheck/nightly or hardware campaign was run under
the PM restriction. Firmware-linked sources are unchanged; flash/RAM were
not measured and no reduction is claimed. STATUS was not edited.

## Remaining work

The requested fail-before/pass-after production fix is incomplete. Changing
capacity, shortening terminal/replay retention, decreasing origin admission
capacity, extending lifetime/attempts or weakening authentication would
breach this PR's constraints. A follow-up must decide how the existing
receiver retention budget and distributed admission can meet the stated
load before M08 can be declared fixed. Owner occupancy work remains V2-16;
RF queue/driver correlation and on-board acceptance remain with the combined
main HIL campaign. #261 cold five-hop establishment and AppObject fixes
are separate work and were not modified.
