# RouteLoom SDK v1 実機検証（2026-09-26 JST、R2 継続）

## 残項目と次の手順

1. **5 台 DevRam mesh**: Node3 の C3 が USB に再列挙されず、現物は 4 台のみ使用可能。USB と電源を現場で点検し、chip-id/MAC を再照合してから Node3 を書き込み、5 台の経路と配送を再試験する。C5 は 0 台なので C3/C5 実機比較には C5 を別途用意する。
2. **reset 後の復旧**: C6 receiver reset 後 60 秒の配送 0/10、4 台同時 reset 後も配送が戻らない。発見、pairwise session、route lease の各状態を両端で採取して原因を特定し、修正後に receiver/relay/全台 reset と counter 非後退を再試験する。
3. **deep sleep 後の配送**: 新規の security partition から開始しても、C3 reference は最初の wake 後に replayed security counter を繰り返し、配送が失敗した。boot lease と送受信 counter の永続化、sleep image の復元、再発見を調べる。経過時間の信頼できる上限は実装されていない。
4. **Site Authority 完了**: R1 で P7、ZeroTouch、承認、GK readback、member 配送まで確認したが、JoinConfirm/GK ACK、revoke 後の実機締め出し、手動 GK 更新、cutover は未証明。R1 の私有 identity backup を必要に応じて戻し、authority Pull の送受信を計測する。
5. **残る実測**: 指定 2～3 hop の強制と経路表収束、100 回の無線配送成功率、group-send の DevRam 対応、EDHOC の個別 crypto 時間と peak heap、C5 実機、LR250 の air rate と独立した損失率を測る。

R1 の全手順と証跡は [R1 時点の報告](2026-09-26-bench-5node-r1.md) に保存した。以下が R2 の最新判定である。C6 は **SDK v1 対象外の実験 target** であり、C6 の結果を C5 の代用として扱わない。

## DevRam 4 台実験

最初の C6 build は component manifest の target 制限で止まった。esp32c6 を **実験用** target に追加した後、reference Node4/5 を IDF v6.0.3 で build し、chip/MAC preflight 後に flash した。[Node4 image](../../artifacts/hil/2026-09-26/images/ref-c-c6-devram/)、[Node5 image](../../artifacts/hil/2026-09-26/images/ref-d-c6-relayfix/)。C6 log は DevRam adoption と Node4↔5 BOUND/REACHABLE を示す。[Node4 boot](../../artifacts/hil/2026-09-26/r2/flash-ref-c/flash-ref-c-boot.log)、[Node5 boot](../../artifacts/hil/2026-09-26/r2/flash-ref-d-relayfix/flash-ref-d-boot.log)。

最初の 4 台送信はすべて NO_ROUTE→DEADLINE_EXPIRED。bridge に R1 の Site identity/GK が残っていたため、私有 backup 後に bridge と ref-a の rlsec を消去した。さらに relay Node5 で BOOTSTRAP_TRANSIT_ROLE を再現し、MemberConfig adoption 時に MeshNode の local role が更新されていないことを特定した。on_member_config で role を反映する小修正を行い、host ctest 95/95 と実機で再試験した。[修正後送信](../../artifacts/hil/2026-09-26/r2/send-relayfix.jsonl) は Node2、5、4、4、2 の 5/5 が delivered / END_RECEIVED。[Node2](../../artifacts/hil/2026-09-26/r2/capture-ref-a-relayfix.log)、[Node4](../../artifacts/hil/2026-09-26/r2/capture-ref-c-relayfix.log)、[Node5](../../artifacts/hil/2026-09-26/r2/capture-ref-d-relayfix.log) は message origin=1 を記録した。

[status/nodes/node-get/diagnostics](../../artifacts/hil/2026-09-26/r2/host-readonly-mixed4.log) は USB 認証済み、protocol error 0。DevRam bridge の nodes source は unsupported で gateway のみを示し、node-get は NOT_FOUND。この構成では host から経路収束と hop 数を検証できない。DevRam group-send も R1 で UNSUPPORTED、別の LegacyFixture/gateway-scoped 構成では group-send 1/1 を確認した。[R1 group result](../../artifacts/hil/2026-09-26/group-legacy-outcome.json)。

100 件予定の rate-limit-aware send は [生ログ](../../artifacts/hil/2026-09-26/r2/traffic100.jsonl) と [集計](../../artifacts/hil/2026-09-26/r2/traffic100.summary.json) の通り、host accepted 21、device delivered 11、残り 10 は IDEMPOTENCY_FULL。この時点で手動停止し、runner も以後は最初の full で止まるようにした。最初の 5 件と合わせて固定 16 entry の device table に達した。受領 11 件の host accepted→delivered 中央値 104.03 ms、最大 257.87 ms。**11/21 は無線成功率ではない**。R1 の別構成では submit 20/20 が END_SDK_RECEIVED だったが、R2 の reset 後 Node2 宛 submit は [INDETERMINATE](../../artifacts/hil/2026-09-26/r2/submit-after-reset-node2-final.json)。

## reset と deep sleep の再現

- [receiver reset](../../artifacts/hil/2026-09-26/r2/reset-receiver-c6/result.json): chip/MAC 照合済み C6 Node4 の RTS を 5.021 秒保持。保持中 1 件は DEADLINE_EXPIRED、解除後 60 秒の 10 件も全件 DEADLINE_EXPIRED。Node4、relay Node5 を個別に reset して BOUND を再観測しても Node4 宛は戻らなかった。
- [4 台同時 reset](../../artifacts/hil/2026-09-26/r2/reset-all-active/result.json): RTS assert skew 0.139 ms、release skew 34.96 ms、操作エラー 0。後続の Node2/5/4 宛 5 件は全件期限切れ。[直後](../../artifacts/hil/2026-09-26/r2/send-after-all-reset.jsonl)、[90 秒超の Node2](../../artifacts/hil/2026-09-26/r2/send-after-all-reset-late.json)。個別 bridge reset 後 Node4 は 2 回 delivered、Node2/5 は期限切れのまま。[再試行](../../artifacts/hil/2026-09-26/r2/send-after-bridge-individual-retry.json)。復旧は宛先依存で、全台復旧時間を報告できない。
- boot count は C6 Node4/5、C3 Node1/2 で増加したが、送受信 frame counter の単調性を読み出せず、counter 非後退は未証明。
- sleep は C3 bridge/reference を別 network の LegacyFixture 静的 peer とし、reference を 20 秒 awake / 10 秒 timer sleep に設定。[image](../../artifacts/hil/2026-09-26/images/ref-a-legacy-sleep-r2/)。最初は既存 state の影響を疑ったため、両 C3 の rlsec をさらに私有 backup 後に消去した。[bridge](../../artifacts/hil/2026-09-26/r2/bridge-rlsec-legacy-clean/manifest.json)、[ref-a](../../artifacts/hil/2026-09-26/r2/ref-a-rlsec-legacy-clean/manifest.json)。
- 新規状態の [sleep 前送信](../../artifacts/hil/2026-09-26/r2/legacy-sleep-clean-baseline.jsonl) は 1/1 delivered、約 103 ms。最初の [wake 後送信](../../artifacts/hil/2026-09-26/r2/legacy-sleep-clean-after-wake.jsonl) は HOP_ACCEPT_TIMEOUT。[serial](../../artifacts/hil/2026-09-26/r2/ref-a-legacy-sleep-clean-cycles.log) は WAKE_DEEP_SLEEP→RESUME_UNCONFIRMED と replayed security counter peer=1 を示す。bounded discovery と信頼できる経過時間上限は未実装で、warm restore/RTC counter 先行更新を合格としない。
- 試験後は chip/MAC を再照合して bridge/ref-a を DevRam image に戻した。[ref-a 復旧](../../artifacts/hil/2026-09-26/r2/restore-ref-a-devram-progress.log)、[最終 USB 状態](../../artifacts/hil/2026-09-26/r2/rig-final-status.log)。最終時点で Node1/2/4/5 は列挙、Node3 だけが OFFLINE。daemon は停止した。

## R1 から引き継いだ P7 と MemberEdhoc

[R1 報告](2026-09-26-bench-5node-r1.md) の P7 は C3 bridge/ref-a の console status→機器内 keygen→PoP challenge→DevCert→identity seal/readback まで通った。R1 MemberEdhoc は Node4 としての再 provision、Site Authority の join request→approve→member、GK2 readback、unicast 10/10、submit 1/1 を確認した。revoke は Site 側 commit と RS/GK epoch 1→2 を確認したが、旧 Node2 への RemovalNotice は unreachable、Site 台帳は allowed_unconfirmed のまま。JoinConfirm、GK ACK、旧 ID の物理的締め出し、手動 GK rotate、cutover は未完了。R2 はこれを完了扱いにせず、DevRam/睡眠試験用に rlsec を backup して切り替えた。
