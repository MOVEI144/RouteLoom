## Ranked remaining candidates and bounded fixes

1. **Gateway Link/End recovery ordering: reproduced software failure.** One
   immediate first send expires after repeated resets. Inspect existing demand,
   discovery reservation and End flight transitions at that cycle's new boot;
   a fix must retry existing pending work within its original deadline and
   retain authenticated boot/context matching. Waiting before all probes would
   conceal this failure and is not a fix. No specific faulty transition is yet
   isolated, so no production patch is claimed.
2. **Retained generation/context and terminal admission pressure: plausible
   C6 candidate.** Quiet requests occupy gateway delivery slots without
   progressing; the quiet run lacks per-peer Link/End/worker counters. C6 has
   32 dedup slots, S3 96. Subsequent main admission fixes preserve End replay
   across refusal; the new low-rate boundary control passes both capacities.
   This does not reproduce retained role/GK changes or sustained multi-source
   pressure. Fix only the demonstrated stale-context/admission transition,
   using existing bank/Owner entries; do not shrink retention or raise capacity.
3. **C6 callback/ACK service, RX overflow or Owner/worker timing: still possible.**
   The tested callback orders, 25 ms delay and one overflow do not reproduce
   0/20. Runtime already serializes the physical TX slot, queues callbacks,
   stages reserved completions on overflow and notifies Owner. The crypto
   worker matches Owner priority after #256. Real FreeRTOS preemption, Wi-Fi
   bursts and crypto occupancy are not modeled here. Do not add an arbitrary
   yield/priority change without a matched timing reproduction.
4. **RF-switch / LR250 / TX-power initialization: lower current confidence.**
   Device configures C6 RF before `runtime.initialize`; power is applied after
   Wi-Fi start; every driver peer gets LR250. These paths do not depend on
   TRACE. The [HC6 control](2026-10-02-hc6.md) also leaves RF failures unresolved.
   Driver/PHY or board timing still needs physical controls; no radio default
   or startup delay was changed.

Next PM HIL: current main, identical roles/generations/peers and shipped dedup,

authenticated boot/session, with immediate >=2 s probes and original thresholds.
