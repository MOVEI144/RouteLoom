## Changes and contracts

The reset-cycle tool now measures recovery at observed delivery completion,
including the send latency. A regression test distinguishes that from request
admission time.

A committed link EDHOC responder can yield its crypto workspace to a waiting
link exchange. Its admitted M4, exact M1/M3 duplicate hashes and original
retry deadline remain in the existing bounded record. The exact installed RX
context, stored in unused retry-buffer space, allows confirmed records to be
retired without retaining the crypto workspace. End-to-end exchanges retain
their existing confirmation rule. A lost admitted M4 is tested while a second
neighbour uses the workspace; altered retries cannot retrieve it.

The manual-plan Owner/MeshNode E2E tests now explicitly use gateway-star
links. Manual plan distribution requires direct gateway bindings. A triangle
could discover the member-to-member leg first. READY counts, authentication,
deadlines and delivery assertions were not relaxed.

No public API, protocol, persisted format, security mode, production default,
capacity setting or capability was changed. No new manager, worker, state
machine or allocated buffer was introduced.
